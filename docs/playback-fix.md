# 播放修复记录（本地修复版 1.2.1）

问题：播放器显示“视频暂时无法加载 / 暂无播放地址”，点击重试不能恢复。

## 原因

- 原有播放 GET 接口仍返回业务成功及分集元数据，但播放地址字段为空。
- 官网已将取址拆分为独立的分集播放 POST 接口，并通过新的加密播放通道传输。
- 前端重试按钮只调用 video.play()；地址获取失败时没有 video 实例，因此不会重新请求。
- 已看过的集数长期复用内存中的旧地址，存在签名过期后无法播放的问题。

## 修复

- 新增 `src-tauri/src/playback.rs`，按照官网公开前端协议实现临时会话、密钥协商及认证加密请求；严格校验会话、序号、时间戳和响应认证标签。
- `api_play` 改用当前分集播放接口，将新响应归一化为前端已有数据格式。线路或登录状态在请求期间发生变化时丢弃回包。
- 网络请求继续使用已有 URL、DNS、内网限制与系统代理；加密会话请求不跟随重定向。
- 前端重试重新取址并重建播放器；切换视频忽略旧请求，返回旧集数重新取址；播放成功清除错误，原生媒体错误也能展示重试入口。
- 本地版本号统一为 1.2.1，用于区分用户提供的 1.2.0 可执行文件。此版本为本地修复构建。

## 验证方法

- `pnpm build`：前端及测试 TypeScript 检查、生产构建。
- 运行 `pnpm dev`，用浏览器访问 `/tests/playback-retry.html`：8 项回归，包括无播放器时重试、旧请求回包隔离、返回条目刷新地址。
- `cargo test --lib`：离线回归。GNU Windows 的库测试程序缺少 Common Controls v6 manifest 时，应将 Tauri 的同类 manifest 加入生成的测试程序；MSVC 构建通常不需要此处理。
- `cargo test --lib playback::tests::live_playback -- --ignored --nocapture`：少量联网烟测，检查取址、HLS 代理改写、16 字节 AES 密钥及一个媒体分片。可通过 `HGHUB_TEST_VIDEO_ID` 和 `HGHUB_TEST_EP` 指定待验证的视频和集数。

联网验证使用截图对应的视频编号 12、第 1 集。无需登录，未改动上游权限或付费判断。

## 本次验证结果（2026-11-12）

- 前端生产构建成功；8 项浏览器播放回归全部通过。
- Rust 离线回归：31 passed / 0 failed，6 项默认忽略的联网测试按需选择执行。
- 截图对应第 1 集：真实取址、清单代理、16 字节 AES 密钥与媒体分片检查通过。
- 原有端到端取流测试已迁移到新接口，并实测通过。
- Windows 10 x64 release 构建成功，文件版本 1.2.1；实际启动后读取到截图对应剧集播放进度 `00:10 / 03:27`，未出现加载错误。
