# 遇到问题怎么处理

先确认在运行本仓库 [Releases](https://github.com/lhl1/HGhubL/releases/latest) 的版本，再按现象处理。保留旧目录，退出旧程序后从新目录启动，可以避免误把旧版当新版。

## 无法启动、空白窗口或缺少组件

1. 将 ZIP 完整解压，不要直接在压缩包里双击 EXE。
2. 确认 `HGhub.exe` 和 `WebView2Loader.dll` 在同一目录。
3. 检查系统已安装 Microsoft Edge WebView2 Runtime；缺失时安装 [微软 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
4. 便携包针对 Windows x64，本轮未验证 ARM64 或其他平台。
5. 若系统提示发行者未知，可先核对 Release 的 SHA256 文件及来源；本版本未承诺代码签名或任何杀毒引擎的检测结果。

## 浏览器能打开站点，软件打不开

浏览器与 Rust 请求层不是同一个网络环境。应用支持固定系统代理及 `HGHUB_PROXY`，不会自动共享浏览器扩展代理；PAC 支持也有限。

- 在设置中检查当前线路，运行网络诊断，记录错误类型。
- 若使用可信的本地代理，可仅在当前 PowerShell 会话中指定：

```powershell
$env:HGHUB_PROXY = 'http://127.0.0.1:7897' # 改成实际监听端口
.\HGhub.exe
```

- 确保代理实际在运行；示例端口不代表软件内置代理。
- 不要把代理用户名、密码或整份环境变量发到公开 Issue。
- 严格模式与自定义 DNS/FakeIP/NAT64 可能有兼容限制，见 [安全说明](security.md)。不建议为了普通播放失败就先关闭安全模式。

## “暂无播放地址”或视频一直加载

- 更新到当前 Release，旧版可能仍使用已经变化的上游取址流程。
- 点击重试，让程序重新获取当前集地址；必要时切换受支持线路再重试。
- 先检查同一线路下公开页面是否可达。单个作品或集数可能在上游本身不可用。
- 缓存异常时可在设置中清理媒体缓存；该操作保留收藏、观看记录和登录状态。
- 提交反馈时提供版本、视频编号/集数、线路、错误文字与操作步骤，不要提供带签名的播放直链。

取址协议适配和失败重试分别属于后端、前端两层。反复点击播放键不能修复已失效的取址流程。

## 全屏又换了视频、丢了进度或返回异常

当前代码通过逻辑索引保护全屏布局变化，并保留媒体元素。

1. 确认 EXE 版本，关闭其他旧实例。
2. 分别测试“全屏窗口”和“全屏”，记录哪一种触发。
3. 写清切换前位于第几个视频、第几集、是否暂停，以及使用鼠标按钮还是 F / T / Esc。
4. 尽量提供无私人信息的短录屏和错误文字。

Esc 在沉浸模式中优先恢复普通窗口，不直接离开当前播放页，这是预期行为。浏览器模拟回归已覆盖相关状态保持，但未代表每种 Windows 原生窗口环境都已实测。

## 全屏里看不到按钮

进入即隐藏，闲置约 1.2 秒后也会隐藏。明确移动鼠标或点击画面即可显示底部控件；细小抖动不会唤醒。拖动进度或展开选集时，控制栏会保持可见。可按 Esc 先退出沉浸模式。

## 下拉菜单第一次闪一下就没了

1.5.5 已修复菜单定位带动外层滚动的问题。确认运行新版；若仍能复现，记录具体筛选框、窗口大小、页面是否仍在滚动、首次或每次出现。页面真正发生外部滚动、窗口失焦时菜单关闭仍是预期行为。

## 热搜还是一整串标签

当前“猜你想搜”会拆分 `#词` / `＃词`，去重并过滤长标题。若上游换成了别的分隔格式，请复制脱敏后的异常词样例与出现页面到 Issue。长词可能显示省略号，点击仍搜索该单个词的完整内容。

## 为什么高分没有排在整个站点最前

评分优先只处理当前已加载作品，没有抓取全站。继续加载会扩大集合并重新排序；首页分别对各板块排序。无评分排后，同分保留源顺序。排行榜原名次不改写，所以排序后看到原第 8 名排在原第 2 名前面是允许的。

## 找不到打分按钮

分数用于展示和选片，不是让用户提交个人评分。当前已移除个人五星选择、提交入口及原生评分提交命令，查看分数无需登录。

## 升级后主题变成跟随系统

1.5.5 的一次性迁移会把旧设置先切换为跟随系统。这是默认外观调整。可到设置选择深色或浅色，新选择之后会正常保存，不会每次启动强制重置。

## 应用图标还是旧的

Release EXE 已嵌入新图标。Windows 的旧快捷方式或任务栏固定项可能保留缓存：退出旧版，取消旧固定项，再从新目录运行并重新固定。无需删除整个系统图标缓存。

## 切线路后需要重新登录

会话绑定具体站点。切换站点不会把旧 token 发送给新站点；旧版缺少站点归属的会话也不会被直接复用。这是保护账号归属的设计。镜像仅提供游客浏览，不支持任意镜像密码登录。

## 收藏或记录不见了

数据由应用标识和本地存储管理，不在 EXE 文件旁边。不要同时修改应用 identifier、清空 WebView 数据或删除整个应用数据目录。若从完全不同的客户端迁移，不能保证使用相同数据结构。先保留旧目录和本地数据，再反馈升级前后版本。

## 检查更新失败

1.5.6 起指向本仓库 Release。GitHub API 可能限流，代理或 GitHub 网络也可能异常。可直接打开 [下载页](https://github.com/lhl1/HGhubL/releases/latest)；无需重复高频点击。更新检查只引导下载，不会自动安装。

## 开发环境问题

| 现象 | 处理 |
| --- | --- |
| 安装时报符号链接 / `ERR_PNPM_EISDIR` | exFAT 不支持符号链接，保留 hoisted 配置；也可换到支持符号链接的磁盘 |
| pnpm 11 提示忽略 `pnpm.onlyBuiltDependencies` | 对应构建许可已放在 `pnpm-workspace.yaml`，不要删除 `allowBuilds` |
| Windows GNU 库测试提示入口点缺失 | 使用 `scripts/test-windows-gnu.ps1` 给测试程序补 Common Controls v6 manifest |
| Linux 上出现 GTK / WebKit 系统依赖错误 | 当前发布目标是 Windows；保留工程不等于已经验证 Linux |
| `/tests/discovery-source.html` 失败 | 它需要另起 1421 端口快照服务，默认测试脚本不包含它 |
| Android 缺 SDK / NDK / JDK | 配置对应开发环境后再生成工程；本轮不提供 Android 包和签名密钥 |
